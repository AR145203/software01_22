# software01_22｜实用智能硬件需求验证

原仓库描述：软件一班项目。

## 项目目标
找到一个真实、重复发生、现有方式解决不好的日常任务，验证独立硬件是否能降低完成成本，再决定是否开发固件。
当前阶段是需求探索；尚未确定用户、设备平台、预算、联网方式或 AI 能力。

首轮可替换假设：面向桌面工作者，用实体按键触发短语音记录，给出可感知确认，减少临时待办遗忘。
这是待验证的工作假设，不代表用户已确认产品方向。若访谈不支持，按证据换题。

## 现在就能开始
无需开发板、安装依赖或购买器件。
1. 阅读 [项目约束](docs/brief.md)，确定一类能接触到的用户。
2. 执行 [V01 首个验证任务](experiments/V01-demand-validation.md)。
3. 用 [访谈模板](research/interview-template.md)记录证据，用 [实验记录](experiments/results/V01-template.md)汇总结果。
4. 根据预先约定的门槛，记录继续、改题或停止的决定，再推进 [后续任务](docs/backlog.md)。

这里的“可执行”指验证流程可立即开展，当前没有可运行的固件或应用。

## 开发进入条件
完成 V01，选定一个场景；明确基线、效果目标、预算上限、供电和联网约束；确认硬件相对手机/人工方案的价值。
先验证按键→输入→确认的闭环。只有证据表明规则或普通记录不足时，才评估 AI。
当前不承诺量产、云服务、多端账户或复杂模型接入。

## 协作
任务以 Issue 跟踪；结果须区分原话、观察、推测和决策。未经参与者同意，不记录音频。
仓库公开：只提交匿名汇总、合成示例和模板；原始访谈、录音、个人待办、密钥留在本地。
许可尚未选定，后续单独确认。
