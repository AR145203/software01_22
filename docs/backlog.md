# 后续 Issue 列表

按顺序推进；后续任务只有满足启动条件才开始。负责人在领取时指定。

## 1. [V01] 验证目标用户需求与实体入口价值
最高优先级；立即可开始。

任务：执行 experiments/V01-demand-validation.md。先完成同一群体的 5 人访谈，达到门槛后再做 3 人共 9 次模拟及对应基线。

验收：提交匿名结果；逐项核对门槛；在 docs/decisions.md 记录继续、改题或停止。

## 2. [V02] 根据证据锁定单一场景和验收指标
依赖 V01 完成。

任务：根据 V01 结果选择一个用户群和一个任务；若证据不足，设计下一轮访谈。

验收：形成一页需求：用户、触发、输入、反馈、基线、效果目标、非目标及反证。

## 3. [V03] 确认资源约束与硬件选型
仅 V02 确认需求后启动。

任务：确认预算上限、已有设备、供电、联网、尺寸与隐私；比较至少两个方案。

验收：提交约束表、候选比较、BOM 估算和选型理由；采购另行安排。

## 4. [V04] 实现并验证最小设备闭环
依赖 V02、V03；未满足时保持待启动。

任务：实现单一触发→输入→成功/失败反馈；只有需求证据支持时才接入语音或 AI。

验收：提供可复现构建与设备验收步骤；按 V02 指标记录至少 20 次闭环的成功率、响应时间及失败恢复。

## 5. [V05] 真实场景试用与下一阶段决策
依赖 V04 验收通过。

任务：邀请至少 3 名目标用户试用 3 天，启动前约定使用频次与效果门槛；记录未使用原因。

验收：提交匿名使用证据、相对基线效果和继续/改题/停止决定；明确下一阶段成本与最大风险。
